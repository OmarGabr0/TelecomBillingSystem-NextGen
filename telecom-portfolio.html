Telecom Billing Pipeline

Seven discrete stages from subscriber activity to web dashboard — each with clear input/output contracts and independent failure domains.

01
Stage 01 — Trigger
Subscriber Activity
Voice calls, SMS messages, and data sessions generate usage events that enter the billing pipeline.
Service ID 1 = Voice Service ID 2 = SMS Service ID 3 = Data
CDR records created
02
Stage 02 — Extract
CDR Generator
Python simulator creates 100 realistic CDRs every 5 seconds using a pool of 20 Egyptian MSISDN numbers. Writes CDR{timestamp}.csv files.
Python 3.x 100 CDRs / batch 002016XXXXXXXX format external fees included
CSV files written to generated_cdrs/
03
Stage 03 — Transform
Mediation Parser
Java parser polls for new CSV files, extracts date from filename, reconstructs full LocalDateTime, validates fields, then batch-INSERTs into the cdr table. Moves files to archive_cdrs/.
Java Batch INSERT Poll every 5s File archiving
INSERT INTO cdr (status = unprocessed)
04
Stage 04 — Queue
PostgreSQL CDR Queue
Unprocessed CDRs accumulate in the database as an implicit queue. The rating engine polls in batches of 50, ensuring no record is double-processed.
PostgreSQL Neon Cloud Batch size 50
Poll unprocessed CDRs every 5s
05
Stage 05 — Rate
Rating Engine
Core business logic. Applies a three-step waterfall charging algorithm: free units → service-specific allowances → monetary ROR. Uses BigDecimal for financial precision and a zone resolver with in-memory pricing cache.
Java 21 BigDecimal ZoneResolver In-memory cache 3-tier waterfall
INSERT rated_cdr · UPDATE customer_profile
06
Stage 06 — Aggregate
Aggregation Engine
Reads customer profiles for the billing cycle, calculates subtotal + recurring fees + one-time fees, applies 10% tax, generates PDF invoices using openhtmltopdf, then resets unit counters for the next cycle.
Java 25 openhtmltopdf 10% tax Prorated calculation Unit counter reset
INSERT invoice · PDF stored at pdf_path
07
Stage 07 — Present
Web Dashboard
Next.js frontend surfaces all data through REST APIs via the API gateway proxy. Subscribers view usage and invoices. Administrators manage customers and contracts.
Next.js 16 React 19 Framer Motion Tailwind CSS JSESSIONID auth
Core Business Logic

Engineering Highlights

The technical decisions that made this system production-quality rather than a toy.

Three-tier waterfall charging algorithm
STEP 01 — FREE UNITS
General pool deduction
Shared monthly allowance applies to any service type. Depleted first before touching service buckets. No charge generated.
→
STEP 02 — SERVICE UNITS
voice · sms · data buckets
Service-specific allowances — minutes for Voice, count for SMS, megabytes for Data. Only consulted after free units exhausted.
→
STEP 03 — ROR
Monetary overage charge
Running on Rate: remaining_usage × price_per_unit → added to ror_usage in customer_profile. Real carrier billing logic.
⚡
Real-Time Rating Engine
Polls unprocessed CDRs every 5 seconds in batches of 50. Loads customer profiles to a local cache per cycle, applies waterfall charging, then flushes batch updates back to the database in a single transaction.
Java 21 · BigDecimal · batch UPDATE · in-memory profile cache
🌍
Zone-Based Tariff Resolver
Resolves tariff zones from the dial destination (Dial-B) for every CDR. International calls apply zone-specific price-per-unit. Zone pricing data is loaded into memory at startup to minimize DB round-trips during high-volume cycles.
ZoneResolver.java · cached pricing map · zone_id → price lookup
🏗️
ETL Pipeline Design
Classic Extract-Transform-Load pattern: Python extracts raw CDRs to CSV, Java parser transforms and normalizes (timestamp reconstruction, field validation), PostgreSQL loads via batch INSERT. File archiving prevents double-processing without distributed locks.
generated_cdrs/ → parse → cdr table → archive_cdrs/
🔀
API Gateway Pattern
Next.js API routes act as a proxy layer between the browser and Tomcat backend. All requests route through /api/* which forwards the JSESSIONID cookie and rewrites the path. Decouples frontend from backend port/location.
Browser → Next.js /api/* → Tomcat :8080 → DB · JSESSIONID rewrite
📄
PDF Invoice Generation
Aggregation engine generates HTML invoice templates, renders them to PDF via openhtmltopdf, and stores the path in the invoice table. Calculates prorated usage for partial billing months and applies configurable tax rates.
InvoiceService.java · openhtmltopdf · 10% tax · pdf_path stored
🎛️
Service Orchestration
Billing_System.sh coordinates all six services with a defined startup sequence. Maven builds are triggered first, WAR is deployed, then each background process is launched with &. A trap handler provides graceful shutdown on SIGINT/SIGTERM.
Billing_System.sh · trap SIGTERM · mvn clean package → Tomcat deploy

Engineering Depth

Project Challenges

The hard problems that made this worth building.

01
Waterfall Rating Correctness
Implementing the three-tier charging algorithm required careful state management — the remaining usage after each step had to be tracked precisely using BigDecimal to avoid floating-point errors in financial calculations. Getting the boundary conditions right (exactly zero remaining units) took several iterations.
02
Timestamp Reconstruction
CDR CSV files encode dates in the filename (CDR20260416120000.csv) and times per row. The parser must reconstruct a full LocalDateTime by splitting the filename, extracting the date component, then combining with the per-row time field — handling edge cases around midnight boundaries.
03
Session Cookie Forwarding
The Next.js API proxy needed to forward the JSESSIONID cookie to Tomcat on every request and rewrite the cookie's path attribute on the response so browsers would include it in subsequent calls. Mismatches in the path caused silent session loss that was difficult to debug.
04
Multi-Service Polyglot Build
Coordinating Maven (3 Java modules at different JDK versions), Python, and Node.js in a single orchestration script required careful ordering of build steps, background process management with &, and a trap handler for graceful shutdown to avoid zombie processes.
Roadmap

Future Improvements

What this system would look like at carrier scale.

Streaming
Apache Kafka
Replace file-based CDR ingestion with real-time Kafka topics. Enables backpressure handling, replay, and horizontal scaling of the consumer (rating engine) independently.
Containers
Docker
Each service containerized with its own Dockerfile. docker-compose for local development replaces Billing_System.sh. Eliminates JDK version conflicts between modules.
Orchestration
Kubernetes
Auto-scaling for the rating engine during traffic spikes, rolling updates, health checks, and service discovery. HPA based on unprocessed CDR queue depth.
Cache
Redis
Replace in-memory zone/pricing caches with Redis. Allows multiple rating engine instances to share pricing data without DB round-trips. Also enables distributed session storage.
Auth
JWT
Replace JSESSIONID session cookies with stateless JWT tokens. Enables horizontal scaling of the Tomcat backend without sticky sessions or a shared session store.
Observability
Prometheus + Grafana
Instrument each service with Micrometer. Track CDR processing rate, rating latency, invoice generation time, and queue depth. Alerting on processing lag or error spikes.
